A **project** is one publishing initiative — a book, a collection of articles,
a podcast series, a video series, or another defined deliverable — moving through **phases** on
its way to done. Typical phases are Rights, Translation, Editing, Typesetting,
and Publication or Print.

Project status, members, notes, and task changes appear immediately while they
save. Project deletion still requires the typed-title confirmation; after
confirmation the project disappears immediately and returns to the list if the
delete fails.

Use **Proposal** for a possible project whose scope and quotation are still
being reviewed. Proposal projects are clearly badged and filterable in the
portfolio, but they do not count toward active delivery capacity, schedule
roadmaps, overdue-project totals, or missing-deadline warnings. Move a proposal
to **Planning** or **Active** in **Project settings** when the work is approved.

## Creating a project

Managers create projects from the **Projects** page, which has three entry
points in the header:

- **New project** — fill in the details yourself. New teammates see **guided
  setup**, which asks a few questions at a time across four short steps (name and
  type, languages and chapters, dates and plan, then a review before you create).
  It always has a **Fill in everything on one page** link if you would rather see
  the whole form at once, and the one-page form has a **Use guided setup** link to
  switch back. Both create the project the same way. Which one you start with
  follows your **Show helpful guidance** setting in **Settings ▸ Profile**.
  Optionally start from a plan template.
- **Plan with AI** — an AI interview drafts phases, tasks, and chapters for you
  to review before anything is created. See *AI planner & document import*.
- **Import from document** — upload an MOU, license, or grant PDF and let AI
  extract the project, budget, and rights for review. See *AI planner & document
  import*.

Members can browse the whole portfolio on the Projects page but don't create
projects.

Managers also have a **Shared MoUs** entry for agreements whose payment depends
on several projects completing. A covered project shows a manager-only banner
linking to the agreement; members cannot see the group, its project
relationships, or its financial allocations.

Choose a **project type** when creating manually. Books contain chapters,
article collections contain articles, podcasts contain episodes, and video
series contain videos. Video series also choose one project-wide **Original** or
**Translation** production mode. Enter one unit per line. Podcasts and video
series automatically create their standard production tasks and dependencies;
other project types can use a compatible plan template for per-unit fan-out.

Book headers and cards distinguish the **current production plan** from formats
the organization has permission to use. The badge can show **eBook for now**,
**eBook only**, **Print planned**, **Print + eBook planned**, or an unset-plan
warning. Print is treated as planned when the team records a print-funding
decision, creates a print run, or adds a print budget. Owning Print rights alone
does not mark printing as planned.

Project headers and cards summarize the strongest funding evidence currently
available. When a budget exists, the badge can show **No project funding**, the
percentage of project funding **promised**, **Project fully promised**, and the
percentage **received**. The explicit **Project** or **Print** wording keeps the
scope clear. Promised funding is kept distinct from money actually received;
the manager health band shows the underlying promised, received, and spent
percentages.

When printing is budgeted and **Print decision not set** is still selected,
Sastra first uses **Funding assigned** on the Print / Ship line. If no funding
is assigned there but the entire project budget is promised or received, the
badge shows **Print covered · promised** or **Print covered · received** because
the full budget includes printing. If only part of the project is funded and
none is assigned to Print / Ship, the badge says **Print funding not assigned**
instead of implying that no money exists.

Book projects also have a **Print plan and funding** setting: **Print
decision not set**, **Print planned · no funding**, **Seeking print funding**,
**Print partly funded**, **Print fully funded**, or **No printing planned yet**.
Use **No printing planned yet** for an eBook-first project that may be printed
later. Use **Print planned · no funding** when a print run is intended but has no
promised funding. An explicit decision takes precedence because general project
funding and owned Print rights do not prove that money is available for a print
run. Managers change it in **Project settings ▸ Print plan and funding**; leave
**Print decision not set** selected to keep using the automatic calculation.

You can change a project's type later in **Project settings ▸ Project type**. The
type also decides which **work path** the project schedules on (**Books** or
**Creative media**) and its default duration, so keep it accurate. Articles,
podcasts, and video series share the default creative path because they use much
of the same staff. A project
with **no type set is treated as a book** — the primary kind — so untyped
imports land on the Books path rather than with articles, podcasts, and videos.

## Finding and sorting projects

Use the controls above the project cards to search by project or reprint, filter
by status, project type, print funding, or operational need, and sort the
portfolio. **Print funding: needs first** groups book projects by their funding
readiness, while the **Needs funding review** filter shows only books that are
not yet funded or marked as not requiring print. The due-date sorts can
put either the earliest or latest deadline first; projects without a due date
stay at the end. For ordinary projects, Sastra uses the rights agreement's
contractual **complete-by date** when one exists, otherwise the project's due
date. This is the same deadline used on **Schedule**. An active reprint uses its
own campaign due date instead. **Recently added** restores the default creation
order.

The main grid is **Current work**. Completed and cancelled projects move into a
collapsed **Project archive** at the bottom instead of competing with live work.
Open the archive, search for a title, or choose **Completed** or **Cancelled** in
the status filter to find one. Archived projects keep their overview, tasks,
chat, rights, budget, files, activity, and other project details.

A completed book or article stays completed when another printing is needed.
Start the new run from its **Print** tab; the reprint has its own tasks, quotes,
funding, payments, status, and due date. While that reprint is active, the title
returns to **Current work** with both **Completed** and **Active reprint** labels.
When the reprint closes, the title returns to the project archive. This keeps the
publication history accurate without hiding operational reprint work.

Completed and cancelled projects are labelled as such anywhere they still need
to appear in a project picker, such as historical correspondence or task
details. New projects can start in Proposal, Planning, Active, or On hold;
completion is a later lifecycle action.

## Reading a project overview

The project overview is arranged in working order. Issues that need action appear
first, followed by project health, the latest team update and linked email, the
full-width **timeline**, the work plan, then project resources and history. This
keeps current decisions above reference material and gives schedules enough room
on smaller screens.

The **Work plan** combines per-phase progress with overall task progress, dates,
and the assigned team. **Project resources** keeps the Google Drive folder and
attached files together, while **Project record** contains recent activity and
production references such as a copyright notice. Empty or short phase lists no
longer create a tall blank area beside files and history. Books show chapters,
article projects show articles, and podcasts and video series show episode/video
progress. The Projects portfolio also shows and filters by project type.

Choose **Add note** beneath an attached file to record context such as its
version, purpose, approval state, or next step. The note appears directly below
the filename and can be edited or cleared later. Notes belong to that attachment,
so the same underlying file can carry different context when it is attached to
another project, agreement, quote, or payment.

On current projects, managers additionally see a compact **Project health**
summary (funding, rights, delivery, workload, impediments, and forecast). Funding
and Rights link directly to their review tabs. Its budget summary separates the
percentage promised from the percentage actually received, alongside recorded
spending; delivery avoids showing an empty chart until there is enough history.
Managers also see a status-update composer for posting progress.
Archived projects keep the update history without showing stale health warnings
or accepting a new status update. Anyone
can **reply** to a status update, and you can **@mention** a teammate in an update
or reply — as well as in **Budget notes** and **Rights notes** — to notify them.
See **@mentions**.

Managers also see **External follow-up** when linked correspondence is waiting
for a reply. It shows the counterparty, current request, owner, last-sent time,
and reminder state. It is derived from correspondence and remains separate from
project lifecycle status and blockers. A manager can review and share the text
as a normal project update when teammates should see it.

The manager-only **Recent correspondence** section shows the three newest email
threads linked to the project, including whether the latest message was received
or sent, a short excerpt from its newest message, the known counterparty, thread
status, and when it arrived. The excerpt excludes repeated quoted reply history
and is shortened responsively. Open a row for the complete thread, or choose
**View all** to open Correspondence already filtered to this project. Print
proofs, quote review, and other print-specific email details remain on the
**Print** tab.

New and edited status updates are reviewed by AI during the daily scheduled
review. The review compares the update with current tasks, blockers, budget,
rights, and deadlines, then shows up to three advisory follow-ups beneath the
update. It may suggest creating a missing task, clarifying an owner or decision,
resolving a blocker, updating the plan, or monitoring a concrete event. It does
not create work, change project status, publish content, or contact anyone.

Managers can **Mark reviewed** after considering an actionable recommendation.
That removes it from the Home and portfolio Overview review queues while
preserving the update and its AI notes on the project. A **Create task**
recommendation includes a prefilled review-first task form; choose the owner and
due date before saving. Editing the original update clears the previous analysis
so the next daily review uses the corrected text.

## Project tabs

Across the top of a project: **Overview**, **Tasks**, **Chat**, **Rights**,
**Budget**, then **Print** (books and articles), **Episodes** (podcasts), or
**Videos** (video series), then **Members**.

## Project settings and deletion

Managers choose **Settings** in the project header from any project tab. The
settings panel scrolls independently while keeping its title and close action
available. To rename the project, select the **pencil beside its name** or open
**Settings ▸ Project name**, enter the new name, and choose **Save name**. The
project link does not change. Use Settings to change the project type, print
plan and funding, **schedule**
(a realistic **start date** and **estimated duration**, which drive the capacity
model — see *Schedule*), or language override. Deleting stays collapsed in the
**danger zone** until opened and requires typing the exact project title to
confirm. It removes the project and its tasks, phases, budget, rights, blockers,
chat, and activity.

## Choose how to create a project

Managers and administrators use **Create project** on Projects. The creation page offers guided setup and a single-page form. Switching between these keeps all entered details. **Import from document** and **Plan with AI** are secondary methods on this page. Leaving an edited form for another method asks you to confirm.

Members can read projects and their team lists. Ask a manager to create projects or change project membership.

Project headers keep status and deadline visible. On small screens, open **Project details** for secondary information. **Project settings** stays explicit; **Project actions** contains completion and document updates.

Pipeline task cells show readable status labels. Use Tab to focus a task and Enter to open the shared task editor. Empty episode and video projects offer managers an add action; searches with no matches offer Clear filters.
