# Keeping user documentation up to date

`content/help/*.md` is the single source of truth for user-facing help. It powers
both the in-app **Help** page and the **assistant** (which answers how-to
questions from these docs and refuses to invent features they don't cover).

Whenever you add, change, or remove a user-facing feature, update the matching
`content/help/<topic>.md` (add a new file for a new feature area) in the same
change — keep its `summary`/`keywords`/`roles` frontmatter current. Stale docs
make the assistant give users wrong or "that feature doesn't exist" answers. See
`.claude/rules/help-docs.md` for details.

# Optimistic UI is the default

Apply the full optimistic UI and action-feedback policy in `AGENTS.md` to every
new or changed user-facing mutation. Decide the interaction class while
designing the feature:

- Optimistically update predictable, reversible creates, edits, toggles,
  reorders, assignments, and confirmed deletions. Snapshot state and roll back
  with clear error feedback if the server action fails.
- Use temporary IDs for pending creates, reconcile with canonical server data,
  prevent duplicate submissions, and avoid blocking unrelated UI.
- Use a focused spinner, pending label, or real progress for uploads, imports,
  AI/external work, email sending, payment processing, and other operations that
  cannot truthfully appear complete yet.
- Never use optimism to skip validation, authorization, review-first workflows,
  or explicit confirmation/send boundaries.
- Keep motion short and purposeful, respect reduced motion, and verify immediate,
  successful, and rollback states.

Reuse `hooks/use-optimistic-action.ts`, `hooks/use-prop-state.ts`, and
`lib/actions/result.ts`. Update `lib/actions/interaction-policy.ts` and its test
when a new client mutation needs classification.

# Organization portability

Treat Sastra as a single-organization product that can be installed for any
translation ministry. Organization identity, aliases/domains, languages,
timezone, territory, currency, publishing/print defaults, finance contacts, and
invoice issuer details come from workspace settings—not constants or prompt
copy. Keep credentials in deployment environment variables.

Use the shared workspace AI context for every feature that reasons about people
or counterparties. Snapshot workspace defaults into new projects and preserve
project overrides. Production bootstrap code may fill missing baseline records
but may not overwrite settings customized by an admin.

# UI/UX browser verification reminder

For UI/UX work, follow the agent-browser workflow in `AGENTS.md`: open the local
authenticated app, verify changed screens in light and dark themes, check desktop
and mobile viewports, and save screenshots under `/tmp` before considering the
interface work complete. Also read the agent-browser lessons learned in
`AGENTS.md` before retrying failed browser commands.

# Authenticated page geometry

`AppShell` owns the signed-in app's centered `max-w-[88rem]` canvas. Pages and
nested layouts under `app/(app)` must not add their own outer
`mx-auto`/`max-w-*` wrapper. Use `PageShell` for vertical rhythm and nest a
`ContentColumn` only around focused forms, correspondence threads, chat, or
prose; primary headers and page heroes stay on the full canvas. Loading and
empty states follow the same rule.

Keep mobile below `lg`, the compact rail at `lg`, and the expandable sidebar at
`xl`. For responsive work, compare `[data-app-canvas]` with `/projects` at the
same viewport and sidebar state, test both sidebar states, and reject
document-level horizontal overflow.

`RouteScrollManager` centralizes authenticated navigation scroll behavior:
forward navigation to a different pathname starts at the top, while browser
Back/Forward restoration and hash targets are preserved. Do not add local
scroll-reset effects or `scroll={false}` without a documented reason.
